# YAML codec 数据语义测试方案

> 文件名沿用历史路径以保持索引稳定；测试目标已迁移为安全 codec、数据语义和标准包络，不测试注释文本保真。

## 1. 测试目标与范围

本方案验证 PyYAML>=6.0 集中式安全 codec 及文件操作层在支持范围内的加载、保存、失败保护和格式兼容行为。测试只把重新解析后的数据类型和值语义作为保存成功标准。

覆盖范围：

- 标准包络：`__data__` 数据根和可选 `__type_hints__` 类型提示；
- raw YAML：文档根直接作为数据树，首次保存后规范化为标准包络；
- 普通映射、序列、标量、嵌套结构和项目允许的类型提示；
- 安全拒绝、候选文件校验、备份和原子替换边界；
- `test_mode` 副本、路径选择和可序列化快照的数据语义一致性。

## 2. 契约与非目标

### 2.1 正向契约

1. 同一 codec 可以读取标准包络和 raw YAML。
2. 标准包络加载后得到 `__data__` 对应的数据树，并正确处理支持范围内的类型提示。
3. raw 输入可以被保存，首次保存的结果包含 `__data__` 与 `__type_hints__` 标准包络。
4. 保存结果用同一 codec 重新解析后，与预期数据树的类型和值语义等价。
5. 语法错误、unsafe tag、重复 key、未声明类型和不支持类型快速失败。
6. 候选文件解析或语义比较失败时，目标文件原始字节保持不变。
7. 测试模式只修改隔离副本的数据；生产源文件、活动地址选择和快照契约保持既定边界。

### 2.2 明确非目标

以下表达允许规范化或丢失，测试不得断言其文本一致：

- 注释、空行、缩进、换行和字段排列；
- 引号样式、flow/block 排版；
- anchor/alias 名称、共享引用表达和其他 YAML 展示细节；
- 原始文本字节和标准化前后的布局。

因此，测试名称、断言和报告不得把注释文本一致性作为通过条件；文件名仅为历史路径兼容而保留。

## 3. 测试分层

### 3.1 codec 单元测试

| 场景 | 输入 | 预期 |
| --- | --- | --- |
| 标准包络 | `__data__`、`__type_hints__` | 得到安全数据树和类型提示 |
| raw 输入 | 映射、序列、标量根 | 成功解析为数据根 |
| 嵌套数据 | 多层映射和序列 | 类型和值保持 |
| 语法错误 | 不完整 YAML | 抛出稳定解析错误 |
| unsafe tag | 任意对象构造标签 | 拒绝，不调用任意构造器 |
| 重复 key | 同一映射重复键 | 拒绝，不选择隐式覆盖值 |
| 未声明/不支持类型 | 超出 codec 白名单的数据 | 拒绝并返回失败 |

### 3.2 文件操作集成测试

- 加载标准包络和 raw 文件，检查公共 API 返回的配置值。
- 变更数据后保存，重新加载候选文件并比较数据语义。
- raw 文件首次保存后检查标准包络键存在，且数据树无意外字段。
- 候选编码、重新解析或语义比较失败时检查源文件字节和备份边界。
- 文件替换使用原子路径；失败时不留下可被当作成功结果的半成品。

### 3.3 测试模式回归

- `test_mode=False` 不创建测试副本转换。
- `test_mode=True` 只在副本中根据 `database.test_address` 选择活动地址。
- 标准包络和 raw 输入使用相同的地址选择规则。
- 生产源文件内容不变，运行时配置和可序列化快照使用副本中的活动值。

## 4. 典型用例

### 4.1 标准包络加载与保存

```yaml
__data__:
  service:
    enabled: true
    ports: [8000, 8001]
__type_hints__:
  service.ports: list[int]
```

加载后修改 `service.enabled`，保存并重新解析；断言布尔值、列表和值类型一致，不比较输出布局。

### 4.2 raw 首次保存

```yaml
service:
  enabled: true
```

加载 raw 文档并保存；断言输出可由安全 codec 解析且包含 `__data__`、`__type_hints__`，数据根语义与输入一致。

### 4.3 安全拒绝

对 unsafe tag、重复 key、语法错误和未声明类型分别执行加载或保存，断言返回失败、错误定位稳定、目标文件未被部分写入。

## 5. 执行与通过标准

建议按以下顺序执行：

1. codec 单元测试；
2. 文件操作和标准/raw 兼容测试；
3. 测试模式与快照回归；
4. 失败保护和原子替换检查。

通过标准：所有支持范围内正例的类型和值语义断言通过，所有安全拒绝用例拒绝，候选失败不改变原文件，且没有任何文本保真断言依赖注释、排版或 anchor/alias 表达。

## 6. 维护规则

- 新增 YAML 行为时先更新 codec 契约，再补充数据语义测试。
- 不在业务模块中直接调用底层 loader/dumper。
- 不以某次序列化输出的具体空格、引号、注释或字段顺序作为回归基线。
- 历史 Sprint、技术验证、诊断和归档文档不由本方案迁移。
