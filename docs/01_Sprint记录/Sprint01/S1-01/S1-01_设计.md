## 3. 代码与接口设计

### 3.1 唯一 owner 与插入位置

`ConfigNode._data` 已承载字典式数据和 `get()/update()`。三个方法放在 `get()` 与 `update()` 之间，使同一 owner 的字典访问接口保持相邻；不新建 helper、基类或映射适配层。

```python
def keys(self):
    """返回配置键视图"""
    return self._data.keys()

def values(self):
    """返回配置值视图"""
    return self._data.values()

def items(self):
    """返回配置项视图"""
    return self._data.items()
```

不增加返回类型导入；局部表达复用 `SerializableConfigData.keys/values/items` 的既有直接代理模式。方法签名不接收额外参数，Python 自身保留错误语义。

### 3.2 数据与动态视图不变量

- `INV-01`：返回对象分别是 `dict_keys`、`dict_values`、`dict_items`，不转换为列表、集合或副本。
- `INV-02`：视图保持 `_data` 插入顺序；`items()` 支持直接二元解包。
- `INV-03`：先取得视图，再经现有 `__setitem__` 或 `__delitem__` 修改节点，原视图反映最新 `_data`。
- `INV-04`：嵌套映射继续由既有 `ConfigNode.build()` 转换；视图暴露 `_data` 中实际保存的 `ConfigNode`。
- `INV-05`：名为 `keys`、`values`、`items` 的配置键继续通过 `node[key]` 或 `node.get(key)` 读取；方法属性保持可调用。
