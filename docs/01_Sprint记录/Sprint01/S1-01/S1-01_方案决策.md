## 2. 需求、约束与可观察结果

### 2.1 当前有效需求

1. `ConfigNode.keys()` 返回当前配置节点的全部键。
2. `ConfigNode.values()` 返回当前配置节点的全部值。
3. `ConfigNode.items()` 返回当前配置节点的全部键值对。
4. 三个方法提供 Python `dict` 同名方法的可观察行为：返回原生动态视图，保持当前 `_data` 的插入顺序、内容和迭代语义，并随 `_data` 后续修改更新。
5. 为三个方法增加完整的聚焦单元测试；实施结果通过 Ruff 和项目现有测试。

### 2.2 当前约束

- `_data` 继续是配置键值的唯一 owner；方法只读取并返回其视图，不复制、转换或缓存内容。
- 嵌套映射继续沿用 `ConfigNode.build()` 的现有转换结果；`values()` 和 `items()` 暴露 `_data` 中实际保存的值。
- `ConfigNode` 的方法名继续占用属性命名空间。配置键若名为 `keys`、`values` 或 `items`，通过 `node[key]` 或 `node.get(key)` 读取；这与现有 `get`、`update` 等方法名的解析规则一致。

### 2.3 一句可观察结果

> 使用方可以直接调用 `config.keys()`、`config.values()` 和 `config.items()`，获得与当前内部字典一致的动态视图，并按标准字典方式遍历键、值和键值对。

## 5. 推荐的最小充分方案

只保留一个候选：在现有 `ConfigNode` 类内增加三个零参数实例方法，直接返回 `_data` 的原生视图。

```python
def keys(self):
    return self._data.keys()

def values(self):
    return self._data.values()

def items(self):
    return self._data.items()
```

### 5.1 变更边界

| owner / 预计路径 | 最小变化 | 责任 |
|---|---|---|
| `ConfigNode` / `src/config_manager/config_node.py` | 增加 `keys()`、`values()`、`items()` 及简短项目风格 docstring | 返回当前 `_data` 的原生字典视图 |
| 聚焦单元测试 / `tests/01_unit_tests/test_config_manager/test_confignode_dict_methods.py` | 覆盖三种视图、空节点、动态更新、嵌套存储值和方法名键访问 | 证明公开方法与当前存储语义 |

该候选复用现有 `_data` 和 `SerializableConfigData` 的代理表达；没有新 helper、状态、缓存、依赖、配置、异常分支或兼容层。

### 5.2 公开行为

- `keys()` 返回 `dict_keys`，`values()` 返回 `dict_values`，`items()` 返回 `dict_items`。
- 视图顺序与 `_data` 插入顺序一致；`items()` 可直接解包遍历。
- 先取得视图、再通过现有 `__setitem__`、`__setattr__` 或删除入口改变节点时，视图反映当前 `_data`。
- 空节点返回相应空视图。
- 方法不接收额外参数，错误语义由 Python 方法签名和底层 `dict` 保持。
