## 首个偏差与机制证据

### 产品链路

没有发现产品行为偏差，静态与动态证据一致：

1. `ConfigNode.__setattr__()` 保存根属性值并向 `_schedule_autosave({name})` 传递 `progress` 根段（`src/config_manager/config_node.py:97-124`）。
2. `_schedule_autosave()` 合并本批次变化根段并把 `_delayed_save()` 交给 timer（`src/config_manager/core/manager.py:709-769`）。
3. `_delayed_save()` 识别唯一根段 `progress`，进入 `_save_config_only()`（`src/config_manager/core/manager.py:393-424`）。
4. `_save_config_only()` 从当前 `_data` 生成序列化数据并调用文件层的 `save_config_only()`（`src/config_manager/core/manager.py:431-454`）。
5. `FileOperations.save_config_only()` 只事务写入主目标，不接收或创建备份（`src/config_manager/core/file_operations.py:85-88`）。

### 正式回归保护

首个已证实缺口位于正式测试组合：

1. `test_root_attribute_passes_keyed_intent` 只断言根属性变化已创建 callback 并记录 `progress` intent，没有触发 callback 或复读磁盘（`tests/01_unit_tests/test_config_manager/test_progress_autosave.py:71-76`）。
2. `test_progress_batch_uses_main_file_without_backup_and_round_trips` 直接写 `core._data["progress"]` 与 `_pending_autosave_roots` 后调用 `_delayed_save()`，验证文件层结果，但绕过公开根属性触发和真实 timer（同文件 `103-117`）。
3. 两个测试分别覆盖链路两端，无法单独证明或守护完整公开链路；本次隔离脚本贯通链路后得到符合期望的结果。

因此，当前证据支持“正式回归保护存在端到端接缝缺口”；产品链路的动态结果与登记边界一致。

## 架构与 ADR

- `ConfigManagerCore` 拥有配置状态、保存触发和模式编排；`FileOperations` 拥有文件事务与备份写入（ADR-001 当前决策 `140-144`）。
- `save_config()` 与 `save_config_only()` 都必须对主目标执行候选验证和原子替换；可选备份是主配置提交后的 best-effort 副作用（ADR-002 当前决策 `150-171`）。
- 当前 `progress-only -> _save_config_only()` 选择发生在 Core 的保存触发边界，主配置事务仍由 FileOperations 完成，符合既有职责与单向依赖。
- 本次诊断没有发现需要修改 ADR 的架构事实。
