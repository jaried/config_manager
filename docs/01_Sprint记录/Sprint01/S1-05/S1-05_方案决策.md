## 2. 冻结需求与可观察结果

### 2.1 当前有效需求

`config.progress` 变化时，`config.yaml` 正常保存变化后的 `config.progress`，且该次保存不触发备份。

### 2.2 保留约束

- 当前产品实现已经满足需求，本方案为该行为建立一条完整的正式回归保护。
- 普通配置变化、混合变化、显式保存、外部文件监视、保存返回值及错误语义继续由现有测试保护。
- 生产模块职责、公开接口、依赖、配置格式和持久化状态保持当前状态。

### 2.3 一句可观察结果

> 正式回归测试通过现有公开属性入口改变 `config.progress`，执行已捕获的自动保存回调后，从 `config.yaml` 复读到新值，并确认备份集合及备份内容保持不变。

## 5. 推荐的最小充分方案

只保留一个候选：在现有 `test_progress_autosave.py` 内，将公开根属性变化测试扩展为一条完整、确定性的回归。

```text
core.progress = new_value
  -> 由现有 get_backup_path 建立一个 sentinel backup 并记录路径、mtime、内容
  -> 现有 CapturingAutosaveManager 捕获 callback
  -> 测试显式 fire()，执行真实 _delayed_save 链路
  -> 复读临时 config.yaml
  -> 断言 progress 为 new_value
  -> 断言只进入 save_config_only
  -> 断言 sentinel 与备份集合、mtime/内容及 last_backup_path 保持不变
```
