## 2. 设计结果

新增一条独立正式回归测试，贯通以下链路：

```text
ConfigManager 实例的公开属性赋值
  -> ConfigNode.__setattr__
  -> ConfigManagerCore._schedule_autosave({"progress"})
  -> 捕获一个真实 callback
  -> ConfigManagerCore._delayed_save
  -> ConfigManagerCore._save_config_only
  -> FileOperations.save_config_only
  -> 主 config.yaml 原子替换
  -> 生产 load_yaml 复读
  -> 备份快照保持不变
```

测试只控制 callback 的执行时点。保存分支判断、序列化、YAML 校验、文件替换和备份行为全部由生产实现完成。

## 4. 测试模块结构

测试文件不新增模块级辅助函数或测试辅助类，只包含导入和一个测试函数，减少新签名和重复代码。

```text
test_tc0021_001_progress_autosave_public_chain.py
├─ 标准四行文件头
├─ datetime / Path / Mock
├─ ConfigManager / ConfigManagerCore / FileOperations / load_yaml
└─ test_tc0021_001_001_progress_public_chain_persists_without_backup(tmp_path)
```

文件头固定为：

```python
# tests/01_unit_tests/test_config_manager/test_tc0021_001_progress_autosave_public_chain.py
from __future__ import annotations
from datetime import datetime
start_time = datetime.now()
```

测试函数末尾使用显式空 `return`。代码行不超过 120 个字符，文件少于 300 行。

## 5. 隔离 ConfigManager 实例

使用实际 `ConfigManager` 类型，绕过全局单例和 atexit 注册，只初始化生产 Core：

```python
manager = object.__new__(ConfigManager)
ConfigManagerCore.__init__(manager)
```

随后设置当前测试独有状态：

| 字段 | 值 | 目的 |
|:---|:---|:---|
| `_config_loaded_successfully` | `True` | 允许 autosave 调度 |
| `_config_path` | `tmp_path / "config.yaml"` | 隔离主配置 |
| `_file_ops` | 真实 `FileOperations` | 使用生产文件事务 |
| `_autosave_manager` | `Mock` | 只捕获 callback，不启动 timer |
| `_watcher` | `None` | 本 Issue 不验证 watcher，并避免线程 |
| `_type_hints` | `{}` | 使用标准包络 |
| `_first_start_time` | 固定 `datetime(2025, 1, 1)` | 生成确定性 sentinel backup 路径 |
| `_autosave_last_time` | `0` | 排除频率保护干扰 |
| `_data` | `{"progress": "before"}` | 建立基线配置 |

该对象不注册全局 singleton，不访问用户配置，不创建 watcher 或后台 timer，测试结束时没有资源需要 teardown。

## 6. 观察 Seam

### 6.1 自动保存 callback

```python
callbacks = []
autosave_manager = Mock()
autosave_manager.schedule_save.side_effect = callbacks.append
manager._autosave_manager = autosave_manager
```

`manager.progress = "after"` 后断言：

- `schedule_save` 调用一次；
- `callbacks` 长度为一；
- pending roots 为 `{"progress"}`；
- pending unknown 为 `False`。

同步执行 `callbacks[0]()`，进入真实 `_delayed_save()`。

### 6.2 文件操作入口

```python
file_ops = FileOperations()
file_ops.save_config = Mock(wraps=file_ops.save_config)
file_ops.save_config_only = Mock(wraps=file_ops.save_config_only)
manager._file_ops = file_ops
```

`wraps` 保留真实实现，只记录调用次数。初始化 sentinel backup 后清空两个 Mock 的调用历史，确保断言只覆盖 progress 变化窗口。

## 7. Sentinel Backup 与主文件断言

### 7.1 建立基线

1. 把 `_data["progress"]` 设为 `"before"`；
2. 调用真实 `manager.save()`，创建主配置和一个 sentinel backup；
3. 保存 `_last_backup_path`；
4. 对 `tmp_path / "backup"` 下全部 YAML 文件记录：
   - 相对路径；
   - `st_mtime_ns`；
   - `read_bytes()`；
5. 清空文件操作入口的调用历史。

### 7.2 触发与结算

1. 执行 `manager.progress = "after"`；
2. 断言只捕获一个 callback；
3. 同步执行 callback，断言返回值为 `True`；
4. 使用 `load_yaml(Path(manager._config_path).read_text(encoding="utf-8"))` 复读主文件；
5. 断言 `saved["__data__"]["progress"] == "after"`。

### 7.3 副作用断言

- `save_config_only.call_count == 1`；
- `save_config.call_count == 0`；
- callback 后的备份路径、mtime 和字节内容与基线完全相同；
- `_last_backup_path` 与基线值相同；
- pending roots 已清空；
- pending unknown 为 `False`。

## 8. 测试独立性与并行性

- 每次运行使用 pytest 提供的独立 `tmp_path`；
- 不调用 `get_config_manager()`，不读取或修改全局 singleton；
- 不启动 timer、watcher、子进程或 worker；
- 不使用 `sleep`、轮询、网络、数据库、邮件或外部服务；
- 不依赖执行顺序，也不读取其他测试产生的文件；
- 不修改环境变量、工作目录、模块全局开关或生产数据；
- 测试函数独立运行与多 worker 并行运行结果一致。

## 9. TDD、验证与失败语义

### 9.1 Red

在文件创建前运行精确目标路径，预期 pytest 返回非零并报告目标文件不存在或未收集到测试。该证据证明 S1-05 的正式回归资产缺失。

### 9.2 Green

新增测试后先运行唯一测试函数。当前产品若符合冻结方案，测试应在零生产代码修改下通过。

### 9.3 Regression

依次运行：

1. 新增测试文件；
2. 现有 `test_progress_autosave.py`；
3. affected suite；
4. 完整 `tests/`；
5. 新增文件 Ruff 检查。

任何新增失败都保留原始命令、退出码和失败签名。禁止通过删除断言、改变期望、增加 skip 或修改既有测试取得通过。
