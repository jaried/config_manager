## 4. 测试 seam 与职责

### 4.1 `CapturingAutosaveManager`

只保存传入的 callback，并在测试控制的时点同步执行。它不判断 `progress`，不替换 `_delayed_save()`，也不创建
真实 timer。

固定方法：

```text
__init__() -> 初始化 callback 列表并显式 return
schedule_save(callback) -> 记录 callback 并显式 return
fire() -> 执行最后一个 callback，把结果先赋给变量再返回
```

### 4.2 `RecordingFileOperations`

继承生产 `FileOperations`，覆盖 `save_config()` 与 `save_config_only()`，只记录调用后委托父类执行真实文件事务。
覆盖方法保持父类函数定义与签名不变。

### 4.3 局部辅助函数

| 函数 | 责任 | 返回 |
|:---|:---|:---|
| `_build_manager(tmp_path)` | 构造最小、已加载、无 watcher 的 `ConfigManagerCore` | 一个 manager 变量 |
| `_seed_main_and_backup(manager)` | 写入 `progress: before`，再创建固定时间 sentinel backup | backup 路径变量 |
| `_snapshot_backup_tree(backup_root)` | 记录相对路径、`mtime_ns` 和原始 bytes | 一个快照字典变量 |

这些函数只属于当前测试文件，不提升为共享 fixture 或通用 harness。所有函数遵守显式 `return`、单一主返回和
每行不超过 120 个字符的项目规则。

## 5. 数据流与观察窗口

```text
建立 manager
  -> 使用生产 FileOperations 写入 progress=before 的主文件
  -> 使用生产 get_backup_path/create_backup_only 创建 sentinel backup
  -> manager._last_backup_path 指向 sentinel
  -> 对 backup 根目录生成 before 快照
  -> 清空 RecordingFileOperations 的观察窗口
  -> manager.progress = "after"
  -> CapturingAutosaveManager 得到一个真实 _delayed_save callback
  -> fire()
  -> progress-only 真实保存链写入主 config.yaml
  -> 生产 load_yaml 复读主文件
  -> 比较保存入口与 backup after 快照
```

测试只控制 callback 的执行时点。保存分支、序列化、候选重载校验、原子替换和备份写入均由生产实现决定。

## 6. 状态与不变量

| 状态 | 必须保持的不变量 |
|:---|:---|
| 公开属性变化后 | callback 数量为 `1`；pending roots 为 `{"progress"}`；unknown 为 false |
| callback 成功后 | pending roots 为空；unknown 为 false；返回值为 true |
| 主文件 | `__data__.progress` 从 `before` 变为 `after` |
| 保存入口 | `save_config_only_calls == 1`；`save_calls == 0` |
| backup | 文件集合、相对路径、mtime 和 bytes 前后完全相同 |
| last backup | `_last_backup_path` 仍指向观察窗口之前的 sentinel |

测试不以日志文本、内存值、调用次数中的任意单项替代完整磁盘和副作用证据。

## 7. 失败语义与停止条件

- 若公开属性变化没有生成 callback，测试失败并定位 keyed intent 链路。
- 若 callback 返回 false 或抛出异常，保留真实失败，不吞异常或扩大容差。
- 若主文件未复读到新值，定位主文件事务或序列化链路。
- 若 backup 快照变化，定位错误进入通用保存或 backup 被改写。
- 若新增测试暴露需要修改 `src/config_manager/`、公开签名、YAML 格式、依赖、pytest 配置或 ADR，立即停止实施并返回
  `solution-decision`；implementation 不自行扩展范围。
- 若完整测试出现与当前 changed paths 无关的既有环境失败，测试报告原样记录命令、退出码和失败签名；不通过修改既有测试取得通过。
