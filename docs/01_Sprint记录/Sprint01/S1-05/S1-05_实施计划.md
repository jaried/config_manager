## 3. implementation_start

在任何测试或配置写入前执行一次：

1. 只读核验 Sprint 状态为 `设计完成`。
2. 核验方案、设计、计划和设计总结版本一致。
3. 核验 `S1-05` 分支以当前 `sprint01` 设计成果为祖先；只同步一次 Sprint → Issue。
4. 创建进行态 `S1-05_方案实施总结.md`。
5. 在 `S1-05_实施记录.md` 写入 `implementation_start`、Sprint/Issue HEAD、计划版本和 target。
6. 把 Sprint 投影更新为 `实施中`。

恢复时先读实施总结与 `implementation_start`；检查点有效则继续，禁止再次同步或改写启动记录。

## 4. P01 TDD 顺序

### 4.1 red：证明正式资产缺失

在新增文件前运行：

```text
python -m pytest \
  tests/01_unit_tests/test_config_manager/test_tc0021_001_progress_autosave_public_chain.py \
  -v --tb=short
```

期望：精确路径不存在，pytest 返回非零退出码。该证据只证明正式回归资产缺失；当前产品行为已经由诊断证明为
有效，不构造错误产品断言。

### 4.2 green：新增最小测试

只创建冻结 owned file。文件必须满足：

- 四行标准文件头；
- 文件名和唯一测试函数名与设计一致；
- 所有函数显式 `return` 或 `pass`；
- 正常路径单一主返回，不使用 `return None`；
- 每行不超过 120 个字符；
- `CapturingAutosaveManager` 只捕获 callback；
- `RecordingFileOperations` 只记录后委托生产父类；
- 使用独立 `tmp_path`，零 sleep、timer、watcher、网络、数据库和邮件；
- 不修改已有测试、fixture、pytest 配置和产品代码。

新增后运行同一命令，期望一个测试通过。

### 4.3 refactor

只有在不改变测试目标、断言强度和生产路径的前提下，才允许删除重复局部表达。禁止提升共享 harness、修改产品
代码或“顺便”整理既有测试。

## 8. 停止与恢复

出现以下任一情况立即停止发布：

- 需要修改 `src/config_manager/`、函数签名、YAML 格式、依赖、pytest 配置或 ADR；
- 测试 seam 必须复制产品保存判断才能通过；
- focused 或 affected 出现本次引入的失败；
- full 失败无法确认是既有环境问题；
- actual changed paths 超过冻结集合；
- 方案、设计、计划或 target 版本漂移。

生产行为偏差返回方案决策；纯环境阻塞保留现场和命令证据。不得删除断言、扩大容差、吞异常、改已有期望或
新增 skip 取得绿灯。
