实施完成要求以下事实同时成立：

1. 新增唯一编号测试文件，实际 changed paths 与冻结集合一致；

3. Green 证据证明新测试在零生产代码修改下通过；
4. focused、affected、full 和 Ruff 均无新增失败；
5. 测试报告包含 `scope`、`environment`、`commands`、`results`、`failures`、`skips`、`evidence`；
6. 实施记录中的方案实施阶段检查单全部为 `pass` 或 `not_applicable`；
7. Issue 成果提交合入 `sprint01`，Sprint 状态更新为“待验收”；
8. 生产代码、公开签名、依赖、配置格式和 ADR 的实际 diff 为零。

## 10. 停止与恢复

### 停止条件

- 输入门禁失败；
- 工作树或分支身份不一致；
- 新测试需要产品修改；
- changed paths 超出冻结集合；
- focused、affected、full 或 Ruff 有新增失败；
- 测试报告证据不完整；
- 合入需要强制覆盖并发提交；
- 验收标准需要变化。

### 恢复动作

- S00：修正输入或 target 后重新执行；
- P01：保留 Red/Green 输出，回退未接受的测试提交；
- S01：保留 P01 package，修复直接质量问题后只重跑受影响门禁；
- 决策缺口：写入遗留问题并返回 solution-decision；
- Git 前移：基于新 HEAD 重新集成，不使用 force。
