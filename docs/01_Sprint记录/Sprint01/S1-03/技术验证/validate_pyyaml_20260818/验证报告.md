# S1-03 PyYAML 数据语义验证报告

## 定位

- 目标：验证不用 ruamel 时，最小 PyYAML 方案能否保持 ConfigManager 可观察的数据语义，并维持“验证后原子替换”的失败安全。
- 模式：独立技术探针；不导入、不执行、不修改产品源码。
- 解释器：`D:\anaconda3\envs\base_python3.12\python.exe`。
- 运行时：Python `3.12.9`、PyYAML `6.0.3`。
- 脚本：`validate_pyyaml_semantics.py`。
- 结果：退出码 `0`；全部 8 组主张通过。

## 验证结论

| ID | 主张 | 结果 | 直接证据 |
|---|---|---|---|
| TV-PYAML-01 | 不能直接把 ruamel 替换成裸 `yaml.safe_load`；复用当前 ruamel YAML 1.2 bool/int/float 完整 resolver 模式后可保持标量类型和值 | pass | 30 项矩阵覆盖符号、下划线、前导零、进制、指数、点前导 float、Inf/NaN、日期和 sexagesimal；裸 PyYAML 有 11 项差异，候选 loader 差异为 0 |
| TV-PYAML-02 | 同一 resolver 同时用于安全 loader 和 dumper 后，mapping、sequence、Unicode、bool、number、null、date/datetime 与易歧义字符串可精确往返 | pass | dump 后重新 load 与原对象逐层类型和值相同；`0123`、`1e3` 字符串被自动加引号；输出不存在 `key:   -` |
| TV-PYAML-03 | 注释、行内样式和 anchor 名称允许规范化时，数据仍保持一致 | pass | 两处注释消失，flow sequence 改为 block sequence，anchor 重命名；重新加载的数据逐层相等 |
| TV-PYAML-04 | 安全 loader 拒绝 Python 对象标签 | pass | `!!python/object/apply` 触发 `ConstructorError`，未执行标签内容 |
| TV-PYAML-05 | 裸 PyYAML 会静默接受重复键；候选 loader 可保持现有 ruamel 的 fail-closed 行为 | pass | ruamel 与候选均拒绝 `value` 重复，裸 `safe_load` 静默取最后值 `2` |
| TV-PYAML-06 | codec 可在 dump 前拒绝未声明类型和非字符串 mapping key | pass | tuple、set、整数 mapping key 三类样本均触发 `TypeError` |
| TV-PYAML-07 | 候选写入或语义验证失败不会覆盖旧目标；成功候选可原子替换并重载 | pass | 不支持对象触发 `TypeError` 后旧文件字节不变；合法 sequence 替换后重新加载相等 |
| TV-PYAML-08 | raw 与标准 `__data__/__type_hints__` 包络都能分别完成安全 dump/load | pass | 两种根 mapping 的键和值逐层相等；solution-v8 可明确选择统一标准包络作为格式规范化 |

## 对方案的约束

1. PyYAML 必须成为正式直接依赖，ruamel 必须从产品、测试和依赖声明移除。
2. 读取和输出必须共享一个 YAML 1.2 resolver；只改 loader 会让内存字符串 `"1e3"` 在下一次加载时变成浮点数。
3. 所有入口复用一个安全编解码 owner，不允许分别调用裸 `safe_load/safe_dump` 形成 schema 漂移；loader 必须拒绝重复 mapping key。
4. codec 在输出前验证声明的数据模型；tuple、set、自定义对象和非字符串 mapping key 等未承诺类型必须失败，不得由 PyYAML 隐式转换。
5. 主配置只允许按“唯一临时候选写入、同 codec 重载并比较、`os.replace`”顺序提交；异常只清理本轮候选，旧目标不变。
6. 注释、空行、引号样式、flow/block 排版与 anchor 名称不再是验收对象；键值、mapping、sequence、标量类型和安全加载才是验收对象。

## 边界

- 这是技术可行性证据，不是产品实现，也不是用户对 solution-v8 的整体批准。
- 探针覆盖代表性 YAML 1.2 标量与保存事务，不声称证明所有第三方 YAML 扩展标签兼容；solution-v8 明确只承诺安全 YAML 数据类型。
- `os.replace` 证明进程级替换边界，不扩张为断电持久性保证。
