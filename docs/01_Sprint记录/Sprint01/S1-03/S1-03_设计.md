## 3. 系统架构与职责

~~~text
调用者
  -> ConfigManager / ConfigManagerCore：状态、模式、标准包络、公开 bool
      -> FileOperations：普通数据准备、候选文件事务、主/备份边界
~~~

| 模块 | 固定职责 | 禁止职责 |
|---|---|---|
| src/config_manager/yaml_codec.py | 唯一 resolver/constructor、safe load/dump、支持类型校验、递归语义比较 | 文件路径、临时文件、backup、ConfigManager 业务键、日志 |
| core/file_operations.py | PathsConfigNode→普通数据；唯一候选生命周期；主保存验证后 replace；备份 best effort | 持有 YAML parser 状态、原始 round-trip 树、comment/anchor 合并、重复键文本修复 |

## 4. yaml_codec 详细设计

### 4.1 内部接口契约

新增模块只导出下列包内接口；不从 config_manager 顶层 __init__ 暴露，不形成用户 API：

| 接口 | 签名 | 调用方 | 返回 / 失败 |
|---|---|---|---|
| load_yaml | load_yaml(text: str) -> Any | FileOperations、facade、测试 | 返回普通安全 Python 数据；PyYAML 解析错误、unsafe tag、重复 key 或 schema 不支持时抛 YamlCodecError |
| dump_yaml | dump_yaml(data: Any) -> str | FileOperations、facade、测试 | 先递归 validate_supported_data，再返回 UTF-8 可写文本；失败抛 YamlCodecError |
| validate_supported_data | validate_supported_data(data: Any, path: str = "$") -> None | dump_yaml、manager 预检 | 成功无返回；错误包含稳定数据路径和类型，不包含敏感值 |
| semantically_equal | semantically_equal(left: Any, right: Any) -> bool | FileOperations、测试 | 比较精确类型和值；不做隐式转换 |
| YamlCodecError | class YamlCodecError(ValueError) | 所有调用方 | 统一表达安全解析、声明类型和往返不一致；保留原异常为 cause |

实现可保留 Yaml12SafeLoader/Yaml12SafeDumper 和 resolver 安装函数为模块私有或测试可导入的内部名字，但所有产品调用点只能经上述接口，不能直接调用 yaml.load/yaml.dump。

### 4.2 YAML 1.2 resolver 与 constructor

loader/dumper 分别复制 yaml.SafeLoader/yaml.SafeDumper 的 resolver 表，删除 bool/int/float 三个默认 tag resolver，再安装完全相同的规则：

| tag | 精确模式 | 首字符 | constructor |
|---|---|---|---|
| bool | ^(?:true\|True\|TRUE\|false\|False\|FALSE)$ | tTfF | SafeLoader bool |
| int | ^(?:[-+]?0b[0-1_]+\|[-+]?0o?[0-7_]+\|[-+]?[0-9_]+\|[-+]?0x[0-9a-fA-F_]+)$ | -+0123456789 | 去下划线与符号；0b/0o/0x 分别按 2/8/16 进制；其他按十进制，使 077 为十进制 77 |
| float | ^(?:[-+]?(?:[0-9][0-9_]*)\.[0-9_]*(?:[eE][-+]?[0-9]+)?\|[-+]?(?:[0-9][0-9_]*)(?:[eE][-+]?[0-9]+)\|[-+]?\.[0-9_]+(?:[eE][-+][0-9]+)?\|[-+]?\.(?:inf\|Inf\|INF)\|\.(?:nan\|NaN\|NAN))$ | -+0123456789. | SafeLoader float |

禁止扩宽 .5e3：只有点前导且指数带显式正负号的 .5e+3/.5e-3 才是 float。null/date/datetime 和其他 SafeLoader 安全 tag 继续沿用 PyYAML safe schema。dumper 安装同一隐式 resolver，保证 yes、0123、1e3 等字符串被必要引用，不在 dump→load 后变型。

批准的标量真源为技术验证脚本 scalar_texts：

yes, no, on, off, true, false, TRUE, False, 0123, 077, 0o17, 0x10, 0b10, +12, -0, 1_000, 1e3, 1E+3, 1.25, .5, .5e+3, .5e3, .inf, .NaN, null, ~, 2026-08-18, 1:20, 1:20:30, plain-text。

实施测试必须对每项同时核对当前批准参考类型/值与 codec 类型/值，不能只比较字符串输出。

### 4.3 安全数据树

允许类型采用 type(x) 精确匹配，不接受子类伪装：

- 标量：None、str、int、float、bool、datetime.date、datetime.datetime。
- 容器：list、dict；dict 的每个 key 必须 type(key) is str。
- 递归路径：mapping 使用 $.key，sequence 使用 $[index]；异常只报告路径与 type 名。
- 明确拒绝：tuple、set、bytes、ConfigNode、PathsConfigNode、自定义对象、非字符串 mapping key 及其他未声明类型。

load_yaml 使用 SafeLoader，因此 !!python/object/apply 等 Python tag 必须在构造前失败。Yaml12SafeLoader.construct_mapping 在每个 MappingNode 中构造非 merge key 并检测重复；同一 mapping 的重复显式 key 抛 ConstructorError。YAML merge key << 继续使用 SafeLoader 的标准合并语义，显式覆盖 merge 来源不是“同一节点重复显式 key”；出现多个同名显式 key仍拒绝。load 完成后再次运行 validate_supported_data，阻止非字符串 key 或未声明的安全构造结果流入产品。

### 4.4 dump 与语义比较

dump_yaml 固定参数：

- Dumper=Yaml12SafeDumper
- allow_unicode=True
- default_flow_style=False
- sort_keys=False

不设置宽度、缩进保真、quote 保真或 anchor 名称。输出换行由写入方以文本模式 newline="\n" 固定。

semantically_equal 规则：

1. type(left) is type(right)，否则 false；bool 与 int 不相等。
2. dict 比较 key 集合和每个 key 的递归值；mapping 迭代顺序不属于语义。
3. list 比较长度、顺序和逐项递归值。
4. float NaN 仅在双方均 math.isnan 时相等；Inf/-Inf 按普通精确值与符号比较。
5. date 与 datetime 因精确类型规则不互换；其他标量按 ==。
6. 对 unsupported tree 不做容错比较；调用方先经 validate_supported_data。

### 4.5 允许的规范化

codec 重载后的数据类型/值必须等价；以下文本或对象身份变化是已批准行为：注释删除、空行/缩进/引号/flow-block 变化、anchor 名称与 alias 表达消失、共享引用展开、mapping 排版变化。测试只能 parse-and-compare，不能恢复文本保真断言。

## 5. FileOperations 保存事务

### 5.1 数据准备

_convert_paths_config_nodes 递归处理：

1. 真实 PathsConfigNode：读取其 _data 并递归转为普通 dict。
2. type(data) is dict：保留字符串 key 与插入顺序，递归值。
3. type(data) is list：保留顺序，递归项。
4. 其他值原样交给 codec 的声明类型校验。

删除 _yaml、_original_yaml_data、_config_path parser 状态以及 _prepare_data_for_save 的 round-trip merge分支；删除只服务旧路径的深合并、anchor/alias 修补、重复键文本后处理、原始树 reload 和无效类型 no-op。不能保留第二条“旧树合并后保存”路径。

### 5.2 唯一候选创建

每次主写入由 FileOperations 在目标父目录创建一个本轮唯一候选：

- 使用 tempfile.mkstemp(dir=target.parent, prefix=f".{target.name}.", suffix=".tmp") 或等价标准库 API 取得唯一实际路径。
- 立即关闭低层 fd，再以 encoding="utf-8"、newline="\n" 打开该精确路径；不复用固定 target.tmp。
- 写入 dump_yaml(data) 完整文本并关闭文件。
- 候选路径仅存在于当前调用局部变量；finally 只 unlink 当前候选且仅在仍存在时执行。
- 不清理目录中的历史 tmp、不使用 glob、不删除目标；不增加 fsync 或断电持久性承诺。

### 5.3 主保存提交顺序

save_config 与 save_config_only 共用一个私有主写入 helper，顺序不可调整：

~~~text
普通数据
 -> validate_supported_data
 -> dump_yaml
 -> 写完并关闭唯一候选
 -> 重新读取候选文本
 -> load_yaml
 -> semantically_equal(reloaded, ordinary_data)
 -> true: os.replace(candidate, target)
 -> false/任意异常: 不 replace，清理 candidate，返回 False
~~~

只有 os.replace 成功后返回主保存成功。目标原先存在时，所有 replace 前失败保持旧 bytes；目标原先不存在时保持不存在。dump、写、关闭、重新读取、load、比较、replace 任一失败都记录现有错误通道并返回 False，不抛给公开 save()；日志不得输出完整配置或敏感值。

save_config(config_path, data, backup_path) 在主目标成功后才尝试 backup：

- backup 失败只记录 warning，不把已提交的主成功反转为 False。
- backup 不参与主目标“成功即重载”门禁，继续保持 best effort。
- save_config_only 使用同一主 helper，覆盖 auto-create 初始化路径。

### 5.4 备份边界

create_backup_only 先做 PathsConfigNode 转换与 dump_yaml 声明校验，再用同目录唯一候选+关闭+os.replace 写 backup；返回自身 bool。它不读/改主目标，不承诺完整 reload compare，不删除非本轮候选。manager 的初始化 backup 继续通过该公开内部边界设置 watcher flag 与 last_backup_path。

## 7. 数据链与集成设计

### 7.1 完整数据链

~~~text
输入 YAML 文本
 -> FileOperations.load_config/load_yaml
 -> 普通 Python 数据
 -> ConfigManager 状态与 standard/raw 业务投影
 -> set()/autosave/test-mode 更新
 -> ConfigManagerCore 标准包络
 -> FileOperations PathsConfigNode 转换
 -> yaml_codec validate/dump
 -> 唯一候选文件
 -> yaml_codec load + semantic compare
 -> os.replace 主目标
 -> ConfigManager clear/reload/get_raw_yaml_content
~~~

| 环节 | 输入 | owner | 输出 | 失败语义 |
|---|---|---|---|---|
| L1 解析 | UTF-8 文本 | yaml_codec | 普通安全数据 | unsafe/duplicate/schema 错误 |
| L2 业务加载 | 普通数据 | FileOperations/Core | raw 或标准业务状态 | 现有加载错误通道 |
| L3 状态更新 | 业务键/值 | ConfigManager | 更新状态 | 公开 API 既有语义 |
| L4 标准化 | 状态/type hints | Core | 标准包络 | 获取可序列化数据失败 |
| L5 路径转换 | 包络/PathsConfigNode | FileOperations | 声明普通数据树 | unsupported type |
| L6 编码 | 普通数据树 | yaml_codec | YAML 文本 | YamlCodecError |
| L7 候选 | YAML 文本 | FileOperations | 已关闭唯一文件 | I/O 失败、不改目标 |
| L8 验证 | 候选文本+原数据 | codec/FileOperations | equal bool | parse/type/value mismatch |
| L9 提交 | 已验证候选 | FileOperations/os | 新目标 | replace 失败、不报告成功 |
| L10 业务复读 | 新目标 | Core/facade | 等价业务数据 | 测试暴露回归 |

### 7.2 接口与集成点

| INT | producer → consumer | 接口契约 | 初始化/顺序 |
|---|---|---|---|
| INT8-01 | FileOperations → yaml_codec | dump_yaml/load_yaml/semantically_equal；普通数据，无路径 ownership 转移 | codec 模块加载后按调用使用，无全局实例 |
| INT8-02 | ConfigManagerCore → FileOperations | save_config/save_config_only/create_backup_only 保持参数与 bool | main target 先成功，再 best-effort backup |
| INT8-03 | config_manager facade → yaml_codec | 字符串 load/dump；业务过滤在 facade | Windows path 文本修复先于 load |
| INT8-04 | yaml_codec → PyYAML | SafeLoader/SafeDumper 子类与共享 resolver | 模块初始化一次复制 resolver，禁止修改 PyYAML 全局类 |

没有网络、数据库、消息总线、前端或跨进程接口。文件路径与 os.replace 属于 FileOperations；schema 不拥有 I/O。模块之间不传递 parser 实例、CommentedMap/CommentedSeq 或候选路径之外的可变全局状态。

## 8. 状态、错误与恢复

| 状态 | 条件 | 可观察结果 | 恢复 |
|---|---|---|---|
| loaded | load_yaml+schema 成功 | 普通数据进入 Core | 无 parser 隐状态 |
| candidate_written | dump 与文件关闭 | 目标仍旧/不存在 | 当前调用持有唯一 candidate |
| candidate_verified | reload 且 semantic equal | 允许 replace | replace 失败仍可清理 |
| committed | os.replace 成功 | 主 save True | 之后 backup 可失败但不反转 |
| rejected | 任一验证前后失败 | 主 save False；旧目标不变 | 清理本轮 candidate |
| backup_failed | 主成功后 backup 失败 | 主 save True + warning | 下次正常保存再尝试 |

错误文本只能包含操作、数据路径、异常类型与目标路径；不能包含完整 YAML、配置字典、数据库地址或其他值。Unsupported type 是调用方可修复的数据问题；parser/duplicate/unsafe 是输入问题；I/O/replace 是环境问题。公开 save bool 继续负责收敛异常，codec 自身保留 cause 便于测试和日志定位。
