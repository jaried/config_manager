## 原始需求映射

base_env 的 alarm_ETFs 需要「通用 config.yaml + 专用 alarm_etfs.yaml」两层配置：专用覆盖通用，记忆型回写只写专用文件（地图票 17）。config_manager 当前只接受一个 `config_path` 并整份回写。

## 方案切片

- Interface：`get_config_manager(config_path, *, base_config_path=None, watch=True, auto_create=False, autosave_delay=None, first_start_time=None, test_mode=False)`；行为按共同方案 §5.2。
- 内部文件：
  - `src/config_manager/core/layered_config.py`（新增）：`merge_layers(base: dict, overlay: dict) -> dict`（mapping 递归合并，其余类型由 overlay 替换，输入不被修改）；`diff_from_base(merged: dict, base: dict) -> dict`（返回 base 缺少或值不同的键，mapping 递归，空 mapping 省略）。
  - `src/config_manager/core/manager.py`：`initialize` 接收并保存 `base_config_path`；`_load` 先加载通用层（同一 `FileOperations.load_config`、同一 `__data__`/原始格式拆包规则）再加载专用层并合并；保存路径（`save`、`_delayed_save`、`_save_config_only`、初始化回写）写入 `diff_from_base(当前数据, 通用层数据)`，`__type_hints__` 只保留差集中的键；`reload` 重读两层；初始化备份只备份 `config_path`。
  - `src/config_manager/config_manager.py`：参数透传；`watch=True` 且给出 `base_config_path` 时抛 `ValueError("base_config_path requires watch=False")`；生产与测试缓存键包含 `base_config_path`；test_mode 只复制专用层，通用层原位只读。
- 失败语义：通用层不存在或加载失败 → 初始化失败，`get_config_manager` 返回 None；保存候选验证失败沿 ADR-002 返回 False 且旧专用文件不变。
- ADR：新增 ADR 草案 [只读基础层与可写覆盖层的双文件配置](../00-联合方案决策/2026-11-04/原子Issue草案/cm-dual-config/cm-dual-config_ADR草案_只读基础层与可写覆盖层的双文件配置.md)。

## 允许范围

`src/config_manager/core/layered_config.py`、`src/config_manager/core/manager.py`、`src/config_manager/config_manager.py`、`tests/01_unit_tests/test_config_manager/` 下新增测试文件、README 中 `get_config_manager` 参数说明段。

## 验收

1. 无 `base_config_path` 时既有测试套件全部通过。
2. 两层合并：专用层同名标量覆盖通用层；嵌套 mapping 逐层合并；列表整体替换。
3. 保存后专用文件只含差集键（含 `first_start_time`、派生 `paths`、专用覆盖项）；通用文件字节在保存、autosave、初始化回写前后完全一致。
4. `watch=True` + `base_config_path` 抛 `ValueError`。
5. test_mode：测试目录只出现专用层副本；通用层不变；`get_serializable_data()` 含合并后的完整键。
6. 通用层缺失时返回 None。
