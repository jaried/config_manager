## 3. 当前基线与技术事实

- `ConfigManager._copy_production_config_to_test()` 在复制完成后调用 `_update_test_config_paths()`；后者位于实例加载前，是批准的唯一转换边界。

## 4. 总体架构与处理流程

```text
get_config_manager(test_mode=True)
  -> _setup_test_environment()
  -> _copy_production_config_to_test()
  -> 临时 YAML 副本
  -> _update_test_config_paths()
       -> 既有路径/时间更新
       -> _select_test_database_address(data_root)
            ├─ 无 database：no-op
            ├─ 有效 test_address：临时 address := 原始 test_address
            └─ 无效：_TestDatabaseConfigurationError
  -> ConfigManager 加载临时副本
  -> cfg.database.address
  -> cfg.get_serializable_data().database.address
```

依赖方向保持 `公开入口 -> 测试环境复制 -> 测试副本转换 -> 窄 helper`。helper 只依赖 YAML 映射接口，不依赖 `ConfigManager` 实例、数据库驱动、logger、Skill 或消费项目。

## 5. 数据、状态与失败设计

### 5.1 数据根与固定键

`_update_test_config_paths()` 已得到 `loaded_data` 后，以现有格式规则取得数据根：当 `loaded_data["__data__"]` 是可变映射时使用该映射，否则使用文档根。随后只检查数据根的 `database`：

- 键不存在：立即返回，不创建节点；
- 节点存在但不是可变映射：抛出专用配置错误；
- `test_address` 必须是 `str` 且 `test_address.strip()` 非空；赋值时保留原字符串，不规范化、不解析、不打印；
- 有效时执行 `database["address"] = database["test_address"]`；允许原 `address` 不存在。

标准与原始 YAML 共享同一 helper，避免两份选择逻辑。键名固定，不读取配置数据内可能存在的普通 `test_mode` 字段。

### 5.2 模式状态矩阵

| API 模式 | 数据状态 | 结果 |
|---|---|---|
| `test_mode=False` | 任意 | 不调用测试副本转换，活动地址不变 |
| `test_mode=True` | 无 `database` | no-op，继续既有加载 |
| `test_mode=True` | `database` 为映射且 `test_address` 有效 | 只在临时副本选择活动地址 |
| `test_mode=True` | `database` 非映射 | 失败，实例不创建 |
| `test_mode=True` | `test_address` 缺失、`None`、空白或非字符串 | 失败，实例不创建 |

没有新增持久状态。成功态只存在于临时 YAML、运行时配置对象和其时间点快照；生产源文件保持字节不变。

### 5.3 接口与异常

建议代码表达如下；名称是内部实现定位，不构成新公开 API：

```python
class _TestDatabaseConfigurationError(ValueError):
    """test_mode 数据库地址配置不满足固定契约。"""


@staticmethod
def _select_test_database_address(data_root: MutableMapping[str, Any]) -> None:
    """在测试副本的数据根中选择活动数据库地址。"""
```

异常消息只允许稳定键路径与原因，例如 `database must be a mapping in test_mode`、`database.test_address must be a non-empty string in test_mode`。不得包含生产地址、测试地址、完整配置或凭据。

`_update_test_config_paths()` 在宽泛 `except Exception` 之前增加专用 `except _TestDatabaseConfigurationError: raise`。这样批准的配置失败不会触发“创建基本配置文件”回退；其他 YAML、文件和既有路径失败继续沿用原语义。

### 5.4 不变量

- `INV-01`：生产源配置内容在成功和失败路径均不改变。
- `INV-02`：无效测试地址绝不产生可用实例或生产地址降级。
- `INV-03`：有效地址按原字符串原样进入临时活动键和快照。
- `INV-04`：`test_mode=False` 与无 `database` 两条保留基线不变。
- `INV-05`：标准格式和原始格式只在数据根定位不同，选择规则相同。
- `INV-06`：异常、日志与测试失败输出不包含地址哨兵值。
- `INV-07`：通用路径逻辑仍只修改既有路径字段；数据库选择是固定键窄例外。

### 7.1 技术验证结论
