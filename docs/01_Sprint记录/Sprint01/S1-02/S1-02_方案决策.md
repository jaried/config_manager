### 2.2 本方案补全、待用户整体批准的约束

原始需求未提供配置键、缺失值行为、`test_mode=false` 行为和 Skill 修改范围。本方案将其具体化为：

- 使用 `database.address` 表示活动数据库地址，使用 `database.test_address` 预配置测试地址。
- 触发源沿用公开 API 参数 `get_config_manager(..., test_mode=True)`；配置数据内即使存在同名 `test_mode` 键，也不反向控制实例创建模式，避免在加载配置前依赖尚未加载的配置值。
- `test_mode=False` 不改变 `database.address`。
- `test_mode=True` 且存在 `database` 节点时，必须有非空字符串 `database.test_address`；否则快速失败，绝不保留生产地址继续运行。
- 不存在 `database` 节点时保持无操作，兼容不使用数据库的通用配置。
- `py-config-logger` 更新入口摘要、完整指南、配置示例、生命周期与失败规则；不增加项目运行时依赖。

这些补全属于完整方案批准对象，尚未被用户单独确认。

## 4. 候选方案结论

采用“在现有测试副本转换阶段执行数据库活动地址选择”的方案：

本节是便于批准的结果摘要；配置行为的候选唯一真源是 §7，系统职责的候选唯一真源是 §6。§9 只投影验收与测试，不重新定义行为。

```yaml
database:
  address: "production-database-address"
  test_address: "test-database-address"
```

```text
test_mode=False
  -> 原有加载路径
  -> database.address 保持生产值

test_mode=True
  -> 复制生产配置到临时目录
  -> 定位 __data__ 根或原始 YAML 根
  -> 校验 database.test_address
  -> 仅在临时副本设置 database.address = database.test_address
  -> 原有 ConfigManager 加载/校验/快照
  -> 调用方统一读取 database.address
```

配置值作为不透明标量处理。`config_manager` 不解析 URL、不拆分连接参数、不导入数据库驱动，也不探测可达性。

## 数据流程图（第 7 节）

### 7.1 配置契约

| 路径 | 类型 | 模式 | 语义 |
|---|---|---|---|
| `database.address` | 不透明标量，实际要求字符串由调用方配置 | 生产/测试活动值 | 调用方始终读取此键 |
| `database.test_address` | 非空字符串 | 测试候选值 | 仅在 `test_mode=True` 时被选择 |

标准配置的数据根是 `__data__`；原始 YAML 的数据根是文档根。helper 必须由现有解析结果确定数据根，不以文件名或字符串搜索判断。

本节中的 `test_mode` 均指公开 API 参数，而不是配置数据里的同名普通键。

### 7.2 模式与失败矩阵

| `test_mode` | `database` | `test_address` | 决策结果 |
|---|---|---|---|
| `False` | 任意 | 任意 | 完全不切换 |
| `True` | 不存在 | 不适用 | 无操作，继续加载 |
| `True` | 映射 | 非空字符串 | 临时副本的 `address` 设置为测试地址 |
| `True` | 映射 | 缺失、`null`、空串或纯空白 | 抛出专用 `ValueError` 子类，停止实例创建 |
| `True` | 非映射 | 任意 | 抛出专用 `ValueError` 子类，停止实例创建 |

当测试地址有效但活动 `address` 不存在时，允许在临时副本中创建 `address`。这让“先配置测试地址”的要求不依赖生产地址是否同时存在。

## 8. 错误、安全、性能与兼容策略

### 8.1 错误策略

- 增加内部专用配置错误，例如 `_TestDatabaseConfigurationError(ValueError)`。
- 既有 `_update_test_config_paths` 的 YAML 兼容回退必须显式重新抛出该错误，不能被宽泛异常处理吞掉后继续加载生产地址。
- 错误消息只指出 `database` 或 `database.test_address` 的键路径和无效原因，不包含任一地址值。
- 文件解析错误、复制错误和既有路径更新错误继续沿用现有处理语义；本 Issue 不重写其异常体系。

### 8.2 安全策略

- 生产配置源文件不可变；测试切换只写临时副本。
- 缺少测试地址时禁止安全降级到生产地址。
- 日志、异常和新增断言不得输出地址值；地址可能内含凭据，应按敏感配置处理。
- 本 Issue 不验证数据库网络可达性，因为那会产生外部连接副作用并把配置库耦合到具体数据库。

### 8.3 性能指标

- 地址选择只做一次常数级映射读取与赋值，不新增文件扫描、网络请求或数据库连接。
- 继续满足现有 `test_mode` 初始化性能目标 `< 2s`；新增聚焦性能断言可复用现有基线，不引入更严的偶然阈值。

### 8.4 兼容策略

- `test_mode=False` 行为保持不变。
- 没有 `database` 节点的通用配置保持不变。
- 有 `database` 节点并启用测试模式的配置必须迁移为显式 `test_address`；这是有意的安全收紧。
- 既有“只改 `base_dir`”设计将更新为“通用路径仍只改 `base_dir`，另有一个明确的数据库活动值安全选择”，不恢复递归路径替换。
